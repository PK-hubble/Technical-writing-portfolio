# Kenneth Peter: Technical Writing Portfolio

Boston, MA · peter.ke@northeastern.edu

These samples document **Notekeeper**, a fictional notes-management REST API that I designed for this portfolio. The product does not exist. I created it so I could show the full range of documentation a developer-facing product needs, written to one consistent set of facts.

| Sample | Type | What it demonstrates |
|---|---|---|
| [API Reference](api-reference.md) | Reference | Precise, scannable endpoint documentation: parameters, responses, errors, rate limits |
| [How-to Guide](how-to-guide.md) | Task-based guide | Step-by-step instructions with runnable code, expected output, and troubleshooting |
| [Release Notes](release-notes.md) | Release communication | Separating new features, changes, fixes, and deprecations, with clear action items for readers |

## Approach

- **Consistency:** field names, limits, and defaults match across all three documents.
- **Reader-first structure:** reference for lookup, guides for tasks, release notes for change.
- **Testable claims:** every example can be checked against the reference.
- **Docs-as-code:** plain Markdown, version-controlled in Git.
